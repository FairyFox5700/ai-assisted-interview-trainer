# Contributing

1. Create a focused branch.
2. Add or update a failing test before production code.
3. Run `dotnet test`, `npm.cmd test`, and `npm.cmd run check` on Windows (`npm test` elsewhere).
4. Keep deterministic checks separate from subjective interview feedback.
5. Do not add analytics, external assets, or AI credentials to the default path.

Pull requests should explain the user-visible change, tests, and any contract change.
